## Story 2: REST Ingest Endpoint

**Objective**: FastAPI server accepting parsed email, routing to agent webhook, returning 250 instantly.

**Files:**
```
src/parousia/
  guard/
    __init__.py
    rest_server.py
    ingest.py
  cli/serve.py
tests/
  test_rest_server.py
  test_ingest.py
```

**What to build:**
- `POST /ingest` endpoint: accept JSON, validate, forward to agent webhook, return `{"status":"accepted","task_id":"..."}`
- `GET /health` endpoint: return Redis + agent connectivity
- `ingest.py`: stdin→parse MIME→POST to localhost:8080/ingest (called by Postfix pipe)
- Agent webhook: POST JSON to configured URL, timeout 5s, queue+retry on failure
- `parousia-guard serve --rest` starts server on 127.0.0.1:8080

**Verification:**
- POST valid payload → 200 with task_id
- POST with missing fields → 422
- Agent webhook unreachable → 200 (queued), task retried
- `parousia-guard ingest < test_email.txt` parses and forwards
- Health endpoint returns Redis status

## Story 3: MCP Outbound Endpoint

**Objective**: MCP server exposing `send_email` tool with rate-limit integration.

**Files:**
```
src/parousia/
  guard/
    mcp_server.py
    email_sender.py
tests/
  test_mcp_server.py
```

**What to build:**
- MCP server on 0.0.0.0:8081 with `send_email` tool
- Tool schema: `to`, `subject`, `body`, `reply_to` (optional)
- Rate limit check before SMTP send (delegates to rate_limiter)
- SMTP send via `smtplib` to localhost:25
- Response: `{sent, message_id, rate_limit_remaining, rate_limit_reset_seconds}`
- Rate limit exhausted → error with retry_after
- `parousia-guard serve --mcp` starts server

**Verification:**
- MCP client connects, discovers `send_email` tool
- Valid send → SMTP delivered, message_id returned
- Rate limit exhausted → error response, no SMTP call made
- Multiple concurrent MCP connections work

## Story 4: Redis Rate Limiting

**Objective**: Token-bucket rate limiter with per-agent (100/hr) and domain-wide (500/day) caps.

**Files:**
```
src/parousia/
  guard/
    rate_limiter.py
tests/
  test_rate_limiter.py
```

**What to build:**
- `RateLimiter` class with `check(agent_id)` → `(allowed, remaining, reset_seconds)`
- Redis-backed token bucket: INCR + EXPIRE pattern
- Per-agent key: `rate:agent:{agent_id}`, TTL 3600s
- Domain key: `rate:domain`, TTL 86400s
- Graceful degradation: Redis down → ALLOW (fail open), log warning
- `parousia-guard status` shows current counters

**Verification:**
- 100 calls within window → all allowed
- 101st call → blocked with remaining=0
- After TTL expires → bucket resets
- Redis down → calls allowed, warning logged
- Domain cap blocks after 500 aggregate

## Story 6: DKIM Setup Commands

**Objective**: CLI command generating DKIM keys and outputting DNS records for Hostinger.

**Files:**
```
src/parousia/
  cli/dkim.py
tests/
  test_cli_dkim.py
```

**What to build:**
- `parousia-guard setup --dkim`: generate 2048-bit RSA keypair
- Store private key at `/etc/parousia/dkim/{domain}.key` (mode 600)
- Output DNS TXT records for copy-paste into Hostinger:
  - DKIM: `default._domainkey` → `v=DKIM1; k=rsa; p=...`
  - SPF: `@` → `v=spf1 mx -all`
  - DMARC: `_dmarc` → `v=DMARC1; p=quarantine`
- `--rotate` flag: generate new key, keep old for 48h overlap
- Validate: check key exists, opendkim configured

**Verification:**
- `setup --dkim` creates keypair, prints all 3 DNS records
- Key file has mode 600
- Second run warns about existing key, `--force` overwrites
- Printed DNS records match RFC format
